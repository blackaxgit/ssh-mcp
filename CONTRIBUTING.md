# Contributing

## Development Setup

Requires Python 3.11+ and [uv](https://docs.astral.sh/uv/getting-started/installation/). CI tests against 3.11, 3.12, 3.13 and 3.14.

```bash
git clone https://github.com/blackaxgit/ssh-mcp.git
cd ssh-mcp
uv sync --locked --extra dev
```

Use `--locked` (as CI does). A plain `uv sync` may re-resolve and rewrite `uv.lock`, which changes the tooling versions the gates run at.

## Running Tests

```bash
uv run pytest
```

For verbose output:

```bash
uv run pytest -v
```

## Code Style

This project uses [ruff](https://docs.astral.sh/ruff/) for linting and formatting, [mypy](https://mypy-lang.org/) for type checking and [bandit](https://bandit.readthedocs.io/) for security scanning. Run them exactly as CI does:

```bash
uv run ruff format --check src/ tests/
uv run ruff check src/ tests/
uv run mypy src/
uv run bandit -r src/ -q
```

Always invoke these through `uv run`, never `uvx`. `ruff` and `bandit` are exactly pinned in the `dev` extra and resolved from the locked environment; `uvx` floats to the newest release, so it reports failures CI does not — and misses ones it does. See the comment in `pyproject.toml` for the incident that motivated the pin.

Every function and method needs type hints, not just public ones — mypy runs with `disallow_untyped_defs`. Type checking covers `src/` only; `tests/` is not checked. New code should maintain compatibility with Python 3.11+.

## Making Changes

1. Fork the repository and create a branch from `main`.
2. Write or update tests for any changed behavior.
3. Ensure the full merge bar passes locally: `uv run pytest`, the four commands under [Code Style](#code-style), and `uv run pip-audit`.
4. Use [Conventional Commits](https://www.conventionalcommits.org/) — `type(scope): subject`, subject-only where possible. Types in use: `feat`, `fix`, `chore`, `docs`, `test`, `ci`. No AI signatures, no "Generated by", no `Co-Authored-By` trailers.
5. Open a pull request with a clear description of the change and its motivation.

`pip-audit` reads the live advisory database, so it can fail on a commit that passed yesterday. Docker builds are additionally scanned with Trivy at `CRITICAL` severity.

## Pull Request Guidelines

- Keep PRs focused on a single change or fix.
- Reference any related issues in the PR description.
- Security-sensitive changes (credential handling, command execution) will receive closer review and may require additional testing evidence.

## Reporting Bugs

Open a [GitHub issue](https://github.com/blackaxgit/ssh-mcp/issues) with:

- ssh-mcp version — `uv run python -c "import ssh_mcp; print(ssh_mcp.__version__)"` from a clone, or `pip show blc-ssh-mcp` for an installed copy. There is no `--version` flag; the only CLI subcommand is `healthcheck`.
- Python version
- Steps to reproduce
- Expected vs. actual behavior

For security vulnerabilities, see [SECURITY.md](SECURITY.md).
